2026 · Solo project · Databricks

Spark Docs RAG Pipeline

Incremental RAG ingestion that embeds only what changed between releases.

The corpus is the Apache Spark documentation, loaded one release tag at a time from v3.5.0 to v4.2.0. Bronze, silver and gold Delta tables in Unity Catalog feed a Databricks AI Search index. Each run diffs the new release against the last committed run, gates the result, embeds the added chunks and applies one MERGE to gold.

  • The v4.0.1 patch release needed 21 of 5,436 chunks embedded.
  • Re-runs are no-ops. They log 0 changed documents, embed nothing and write no new Delta version.
  • 9 chunk checks and 5 vector checks run before gold changes, with drift thresholds calibrated on 42 past releases. Three canary texts must reproduce their committed vectors, which catches a changed model or library.
  • Dev after three upgrades and prod after one full load hold the same 6,051 chunk IDs.
  • 17 design decisions are written up with the options considered, D-001 to D-017.

2026 · Solo project · Evaluation

retrieval-gate

A CI check that fails a pull request when retrieval quality drops.

Each config picks a chunker, an embedding model, whether BM25 is fused with dense retrieval, and whether results are reranked. Every config is scored against a graded golden set built from the Kubernetes Tasks docs. A pull request whose hit@5 drops past the threshold fails, and the Action edits one PR comment with the before and after table.

  • Two different LLM judges grade the golden set. Cohen’s kappa measures their agreement, every disagreement goes to a human, and the freeze step refuses to run until each one is resolved.
  • Labels anchor to character spans instead of chunk IDs, so one frozen set scores any chunker.
  • The candidate pool is the union across configs, so the labels don’t favour the config that found them.
  • A script rejects any number in the README that doesn’t appear in a results file.

2026 · Solo project · Ingestion

jobscan-de

Hourly ingestion from 372 company job boards into a scored daily digest.

It polls applicant-tracking systems such as Greenhouse, Lever, Ashby, Workday, Oracle and SmartRecruiters every hour through their public endpoints. It filters to India-based data engineering roles, fetches the full job description, scores it against a weighted skill profile and emails a digest that opens with the roles to apply to first.

  • Filters were calibrated against a live poll of every board: 52,969 roles, 27,304 of them in India.
  • Each board’s health is tracked. One that fails for 6 hours, or returns 0 roles after having 5 or more, is listed under BOARDS DOWN.
  • An early version marked stale roles as seen and hid 547 open roles. The state file now records only what was actually emailed, and can be rebuilt from the pipeline log.
  • GitHub’s scheduler dropped most hourly runs, so an external cron triggers the workflow through the API.

Approach

How I keep a pipeline honest

  • Numbers come from runs

    If a figure is in a README, the raw output that produced it is committed next to it. In retrieval-gate a script fails the build when the two disagree.

  • Re-runs change nothing

    A write is skipped when its input is identical, so a retry can’t double-count rows or add noise to a table’s history.

  • Gate before you write

    Quality checks, canary vectors and fingerprints run before the published table changes. A failure leaves it exactly as it was.

  • Write the decision down

    Each significant choice gets an entry with the options considered and the evidence. Known limitations go in the README where a reviewer will see them.
